# 새글 Android — Gemma 문장 준비 UI

작성: 2026-09-09. 적용 범위는 Android 앱이다. `admin/design.md`의 광고 운영 콘솔은 적용하지 않는다.

## 브리프와 방향

- 무엇을: Gemma 모델 준비와 문장 사전 생성, 입력 중 즉시 조회를 이해할 수 있는 앱 홈·온보딩·AI 설정·준비 화면.
- 누구에게: 새글을 설치한 한국어 사용자. 현재 상태와 다음 행동을 스스로 찾을 수 있어야 한다.
- 제약: 기존 Android Views/Preference/MaterialComponents, 한국어, 기존 브랜드·데이터·모델 동의·debug 경계 유지. 실제 추론 없이 에뮬레이터에서 UI를 검증한다.

전체 경로 0→6을 Android에 맞춰 적용한다. 컨셉은 **글쓰기를 방해하지 않는 차분한 준비 도구**다. swiss-minimal의 정렬·타입 위계와 새글의 네이비/아이보리/제이드를 사용한다. 과감한 선택은 준비 화면에서 긴 실험 설명을 접고 준비 상태를 가장 크게 보여주는 것이다. 시스템 뒤로가기와 입력기 활성화/선택 흐름은 유지한다.

## 근거

- 브랜드: `docs/brand/README.md`. Ink Navy `#101827`, Warm Ivory `#FFF9ED`, Fresh Jade `#55D6A6`.
- 터치: [Android Views 접근성](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views). 조작 영역 최소 48×48dp. 본문을 불필요한 contentDescription으로 중복 읽지 않는다.
- 확대: [Android 14 글꼴 확대](https://developer.android.com/about/versions/14/features). 200% 확대 상태에서도 줄바꿈과 스크롤로 모든 행동에 접근한다.
- 진행 표현: [Android 진행 표시기](https://developer.android.com/develop/ui/compose/components/progress). 다운로드는 실제 byte/total, 미확정 생성 시간은 임의 퍼센트나 남은 시간을 표시하지 않는다.
- 기존 화면: 기본 Preference 목록, 두 단계 입력기 설정, 세로로 나열된 Gemma 실험 컨트롤. 기존 기능과 상태 연결은 유지하고 시각적 우선순위를 바꾼다.

색은 `saegeul_*` 리소스로 공유한다. 타이틀 28sp, 섹션 20sp, 본문/버튼 16sp, 짧은 보조 라벨 14sp. 한국어 본문은 16sp 이상과 자연스러운 줄바꿈을 유지한다. Android 기본 글꼴 및 사용자 접근성 설정을 존중하며 UI 작업으로 새 폰트 다운로드 의존성을 추가하지 않는다. 간격 4/8/12/16/24/32dp, 본문 좌우 24dp, 주요 표면 모서리 20dp, 버튼 12dp, 최소 조작 높이 48dp. 넓은 창에서는 읽기 영역 최대 640dp를 제품 기준으로 적용한다. 높이는 내용에 따라 늘고 화면은 스크롤한다.

웹 전용 SVG/WebGL/DOM 감사 도구 대신 Android 실제 캡처·View hierarchy·탭/뒤로가기 검사를 사용한다. 이미지 장식·추가 런타임·상시 애니메이션은 넣지 않는다. UI 갱신 중 모델/은행 원문을 메인 스레드에서 읽지 않는다. 생성 정책·추론 경로는 이번 UI 작업으로 변경하지 않는다.

## 화면 계약

- 홈: debug에서 언어 금고를 문장 준비와 개인 입력 관리의 단일 진입점으로 사용한다. 금고 상단에서 Gemma 문장 보강·자동 옵션·실제 상태를 확인한다. 공개 생성 재료와 개인 입력의 저장소·통계는 구분한다.
- 모델 관리 하위 화면: 기존 제목 `AI 문장 준비`, 보조 `Gemma · 기기 안에서 준비`와 모델 다운로드·가져오기 기능을 유지한다. 일상적인 보강 조작의 진입점은 금고다. 자동 보강은 배터리 30% 이상, 명시적 수동 보강은 20% 이상에서 시도하며, 심한 발열·절전·입력 중에는 중지함을 읽기 쉽게 알린다.
- 준비의 실험 상세: CPU/GPU, 메모리·생성 시간·원문 출력·고정 생성·모델 삭제는 기본 접힌 `고급 실험 설정` 안에 둔다. 기존 취소·삭제 확인 및 모든 기능은 유지한다.
- 온보딩: 기존 활성화→선택 두 단계를 보존한다. debug에서 Gemma는 모델을 따로 준비해야 한다는 안내를 보여주되 다운로드/자동 생성을 강제하지 않는다.
- AI 설정: 언어 금고에서 기기 내 문장 보강과 개인 입력을 관리하도록 연결한다. 모델 다운로드와 실험 상세는 `모델 관리` 하위 화면으로 둔다. 외부 글쓰기 AI, 음성, GIF 기능을 Gemma로 허위 재명명하지 않는다. 계정/자격증명/외부 통신 동작은 유지한다.
- release에는 debug Gemma 기능과 안내를 노출하지 않는다. 릴리스 승격·AI 성능 보장·지표 계산 변경은 범위 밖이다.

## 완료 기준

2026-09-10 연장: 사용자 요청으로 금고와 문장 준비의 진입점을 통합한다. 토큰은 유지한다. 상단 Gemma 구역의 기본 언어는 한국어이며 본문 16sp·조작 높이 48dp 이상을 유지한다. 자동 보강은 명시적 토글, 한 번 보강은 별도 요청으로 동작하고 화면을 닫아도 예약을 유지한다. 켜짐·예약·실행·조건 대기·오류·저장 결과를 구분하며 임의 진행률이나 성능 향상을 표시하지 않는다. 사용자별 분석과 일반 문장 생성의 범위를 혼동시키지 않는다. 이 연장 작업의 실측 검증은 이전 결과와 별도로 기록한다.

추가 UI 계약: 금고 상단 `언어 금고 보강`은 개인 입력 반영과 Gemma 수동 예약의 단일 제어점이다. 두 작업의 상태와 시작은 독립적이며, Gemma 모델이 없어도 개인 입력 반영을 막지 않는다. Gemma가 실행 중이거나 수동 요청이 남아 있을 때만 같은 Gemma 요청을 막는다. 모델 관리는 별도 행동이며 하단의 중복 개인 입력 반영 버튼은 숨긴다. 개인 금고 원문은 Gemma 공개 문장 생성에 전달하지 않는다. 모델 없는 오프라인 UI 계측·200% 글꼴 검증과 A35 모델 탑재 기기의 실제 통합 버튼 터치·화면 이탈 뒤 저장은 완료했다. 광고가 포함된 E2E와 Fold6 최신 설치·터치 검증은 별도 범위다.

실제 앱을 에뮬레이터에 설치하여 홈/온보딩/설정/준비 화면과 고급 펼침을 확인한다. 밝음·어두움, compact·넓은 창, 글꼴 200%를 캡처하여 가독성·잘림·접근 가능한 버튼·뒤로가기를 확인한다. 모델 없는 상태의 동의 및 동작을 검사하며 모델을 내려받거나 가짜 준비 완료를 만들지 않는다. 단위 테스트와 APK 빌드를 통과하고, 실제 Fold6 추론 검증과 UI 검증은 구분해 기록한다.

## 구현 평가와 검증 결과

2026-09-10 금고 통합 연장: 자동·수동 Gemma 보강 카드를 통합하고 홈 카드의 목록 구분선을 제거했다. 확대 시 toolbar 제목을 침범하던 시각 표시를 별도 행으로 옮기고, 하단 navigation inset을 scroll viewport 바깥 여백으로 반영했다. 기본·야간·200%·800dp 조작 계측은 각각 통과했고 Fold6의 홈·금고 실제 화면도 확인했다. 800dp에서 기존 최대 읽기 폭 640dp 제한은 아직 적용하지 못한 별도 항목이다. A35에서는 실제 Gemma 수동 백그라운드 생성이 0→8 공개 문장 재료 증가로 통과했다. A35 숫자·기호 자판 첫 입력 16키 실기기 계측도 29~72ms로 통과했지만, 다른 앱·연속 고속 타이핑·Fold6의 모든 입력 상황까지 완료한 것은 아니다. Fold6 자동 보강 원래 설정 복원이 우선이다. 명령과 증거는 `../docs/logs/2026-09/gemma-unified-vault-2026-09-10.md`에 기록했다.

단일 보강 제어점은 모델 없는 오프라인 계측에서 기본·글꼴 200%가 각각 통과했다. 통합 경로의 Toast가 결과를 덮는 문제를 제거했으며, 이전 온라인 실패는 개인 입력 반영 뒤 광고 화면이 focus를 덮은 것으로 확인했다. 광고 정책은 바꾸지 않았다. A35의 모델 탑재 기기에서는 실제 버튼 터치 뒤 HOME으로 나간 뒤에도 10개 문장이 추가되고 중지 뒤 재적재가 보존됨을 확인했다. 광고가 포함된 E2E와 Fold6 최신 설치·터치 검증은 남아 있다.

최종 arm64 앱과 계측 APK의 SHA-256을 확인하고 arm64 빌드와 release Kotlin 컴파일을 통과했다. 단일 보강 APK는 Fold6에 Taildrop 전송했으나 전송은 설치가 아니며, 연결이 끊긴 두 기기에서 최신 통합 버튼을 검증한 것으로 기록하지 않는다.

홈·온보딩·AI 설정·Gemma 준비 화면의 구현을 수용했다. 실제 캡처에서 발견한 온보딩 버튼 그림자와 하단 정렬, AI 설정 요약의 앱 언어 불일치를 보정했다. 최종 x86_64 APK 빌드는 통과했다.

Gemma 준비 화면은 밝음·어두움·글꼴 200%·800dp 창에서 단일 계측 테스트를 각각 통과했다. 홈의 기본/200% 화면, 홈→Gemma 진입, AI 설정의 한국어 요약, 온보딩의 기본/200% 스크롤 화면도 확인했다. 홈의 어두움/넓은 창 및 온보딩의 모든 전이를 검증했다고 확대 해석하지 않는다. 명령·APK 식별자·캡처·환경 장애와 검증 한계는 `../docs/logs/2026-09/gemma-ui-redesign-2026-09-09.md`에 기록한다. Fold6 추론 품질 검증은 휴대폰 연결 복구 이후 별도 진행 대상이다.

2026-09-12 자동 문맥 추천 국소 변경: 기존 Gemma 문맥 패널에 debug 전용 opt-in과 CPU 호환 모드를 추가하고, 기존 후보 바에 실제 생성 접미부의 단어·문장 표시를 연결했다. 기존 PanelStyle과 테마를 유지한다. 자동 후보가 있는 2행은 각 48dp와 구분선 1dp를 위한 97dp 영역을 사용한다. 코드 검토와 debug 빌드·release Kotlin 컴파일·46개 단위 테스트는 통과했다. 실제 자동 IME 계측은 접힌 도구 모음 접근 단계에서 실패했으므로 스위치 표시, 후보 행 높이, 후보 터치·적용의 렌더 검증은 미완료다. 상세 재개 조건은 docs/logs/2026-09/gemma-automatic-context-2026-09-12.md에 기록했다.

2026-09-12 Fold6 wireless 검증 갱신: 실제 IME 테마에서 SwitchCompat의 초기화·터치 문제가 확인되어 두 제어를 플랫폼 Android Switch로 수정했다. 실제 패널 진입과 opt-in, 두 자동 후보 표시, 문장 후보 터치 적용을 통과했다. 두 후보 터치 영역은 각 108px였으며 PNG를 직접 확인했다. 글꼴 확대·다크모드·한글 조합 중 입력과 전체 회귀는 이번 증거에 포함하지 않는다. 결과는 docs/logs/2026-09/gemma-automatic-context-2026-09-12.md의 Fold6 절에 기록했다.

## 2026-09-26 키보드·테마·메뉴 리디자인 (전체 경로, 1~3라운드·K5~K7 반영 완료 — ec872659·18402aa2, 남은 확인 항목은 본문)

### 브리프

- 무엇을: 키보드 본체 사용성(1순위) → 테마 편집·기본 테마·효과 정리 → 메뉴·설정 구조. iOS 동시 적용은 범위 밖(Android 확정 후 1:1 이식, 가정).
- 누구에게: 새글로 매일 한국어를 입력하는 사용자. 오타 없이 치고, 숫자·기호를 짧은 동선으로 오가고, 폴드·한손·가로 화면에서도 편하게 쓰는 것이 목표 행동.
- 제약: Android Views/Preference, 기본 언어 ko-KR(영어 보조), 브랜드 네이비·아이보리·제이드, 후보 바 높이 고정 계약 유지, 테마 저장 스키마(3.0) 하위 호환, 공유·가져오기 신규 기능은 범위 밖. 톤은 사용자 답변 그대로 "차분한 도구 확장이 기본, 사용자의 의지에 따라 표현적 꾸미기를 극한까지".

### 방향

- 컨셉: **조용한 기본, 깊은 서랍.** 키보드와 앱은 글쓰기를 방해하지 않는다. 꾸미고 싶은 사람에게는 서랍을 열면 끝까지 가는 층이 있다.
- 프리셋: swiss-minimal(기존 결정 계승).
- 표면 다이얼(표현성/밀도/모션): 키보드 본체 1/2/1, 앱 설정 1/2/0, 테마 편집기 쉬운 층 1/1/1, 깊은 층 3/3/3.
- 표현 리스크: 깊은 층의 극단적 꾸미기를 허용한다. 안전망은 키 글자 대비 경고와 자동 보정(조사한 키보드 테마 편집기 어디에도 없던 장치).

### before 감사 (에뮬레이터 1080×2400 420dpi, API 34, 캡처 `.artifacts/design-audit-20260926/before/`)

1. 두벌식 자모 키 길게 누르기가 숫자·쌍자음을 주지 않는다. 키 아래 힌트(1, @ 등)는 "스와이프/길게 누르기 기호"로 설계됐으나(`TextKeyboard.kt:31`) 한글 모드에서 `PopupPreset[자모]`가 없어 팝업이 사라진다(`PopupComponent.kt:158`). 숫자 행 고정 시 영문도 힌트(`%^&…`)와 팝업(`1`)이 어긋난다.
2. 가로 모드에서 키보드+툴바+후보 두 줄이 화면을 채워 입력칸이 보이지 않는다(툴바·후보만 높이의 35%). 키 폭 약 72dp로 과도하다.
3. 키 글자가 시스템 글꼴 크기를 따르지 않고 크기 설정도 없다(코드 고정 19~30f).
4. 한손 모드·가로 최대 폭이 없다.
5. 테마 편집기: 효과가 위, 바탕·강조색이 아래로 과업 순서가 거꾸로다. 섹션마다 다른 선택 칩 색(보라·분홍·파랑·빨강 하드코딩), 이모지 장식 칩, 금색 칩 위 흰 글씨. 프리셋 적용 시 "어두운 키" 스위치 리스너가 연쇄로 돌아 프리셋을 반투명 템플릿으로 덮어쓰고, 프리셋·스위치 모두 효과와 키별 스타일을 초기화한다(`CustomThemeActivity.kt:622-623, 1404-1406`).
6. 테마 목록 섬네일에 이름이 없다. 새 테마 타일이 fcitx 일러스트다. 편집기에서 색 21개 중 8개만 편집된다. 앱 코드에 대비 보호가 없다. 효과가 절전·애니메이션 끔을 무시한다.
7. 가상 키보드 설정 34항목이 그룹 없이 진동·소리부터 나온다. 기호 화면 탭에 `[全]` 한자 아이콘.
8. 리턴 키: 연한 제이드 위 흰 아이콘, 비텍스트 대비 3:1 미달 의심.

### 라운드 1 결정 — 키보드 본체

- **K1 길게 누르기 = 보이는 힌트.** 알파벳 키 길게 누르기 팝업의 첫 항목과 기본 선택은 항상 키에 보이는 보조 글자(스와이프 기호)와 같다. 한글 모드에서는 둘째 항목으로 Shift 자모(ㅃㅉㄸㄲㅆㅒㅖ)를 준다. 자모는 문자열 커밋이 아니라 해당 영문 대문자 키를 fcitx에 보내 조합 엔진이 조합한다(표시는 자모, 전송은 `Q` 등). 한글 모드에서 라틴 악센트 문자는 보이지 않는다.
- **K2 키보드 틀(frame) 기본 요소.** 키보드 좌우 여백을 계산하는 순수 함수 하나가 사용자 여백·한손 모드·가로 최대 폭을 결정한다. 한손 모드는 끔/왼쪽/오른쪽, 폭 84%, 빈 쪽에 "반대쪽으로"·"한손 모드 끄기" 48dp 버튼. 분할 키보드가 켜진 폭에서는 한손 모드를 적용하지 않는다. 가로(분할 아님)에서 키보드 최대 폭 640dp 가운데 정렬(앱 읽기 영역 최대 640dp와 같은 값).
- **K3 키 글자 크기 배율.** 80~140%, 5% 단위, 기본 100%. 모든 자판의 주 글자와 보조 글자에 곱한다.
- **K4 키 간격·모서리 기본값은 바꾸지 않는다.** before 캡처에서 기본 간격이 오타 원인이라는 근거를 찾지 못했다. 적응형 히트 영역은 입력 로그 기반 후속 과제다.
- `[全]` 기호 탭 아이콘은 한글 표기로 바꾼다.
- **K5 가로 후보 바 1줄 고정(사용자 확정 2026-09-26).** 가로 모드(분할 아님)에서 후보 영역은 48dp 한 줄로 고정한다. 단어 후보와 문장 추천이 한 줄을 나눠 쓴다. 세로의 2행 고정 계약(97dp)은 그대로다. 높이가 입력 중에 바뀌지 않는다는 원칙은 가로에서도 유지한다.
- **기본 키보드 테마를 새글 테마로(사용자 확정 2026-09-26).** 새글 아이보리(라이트)·새글 네이비(다크)를 추가하고, 테마를 직접 고른 적 없는 사용자의 기본값을 PixelLight/PixelDark에서 바꾼다. 2라운드에서 구현한다.
