# 독립 포크 전환 리팩터 팩

## 목표와 비목표

목표는 기존 동작과 84개 커밋을 보존하면서, 저장소·공개 식별자·라이선스·배포 검증의
소유권을 독립 포크로 옮기는 것이다.

첫 기준 태그에서 제품 이름, Play 등록, 서명 키를 임의로 확정하지 않는다. 내부 Kotlin
namespace 전면 변경과 한글 플러그인 메인 APK 번들링도 이번 패치의 비목표다.

## 불변 조건

- 기존 84개 커밋과 현재 미커밋 제품 변경을 잃지 않는다.
- 84개 작업의 분기점 `0eb0e069...`와 최신 upstream의 추가 15개를 구분해 기록한다.
- 기준 태그 전에는 최신 upstream을 merge/rebase하지 않는다.
- 기존 앱의 입력, AI, 음성, OCR, 사전, 플러그인 동작은 기준 태그에서 바꾸지 않는다.
- 서브모듈 해시는 태그가 기록한 값과 정확히 일치해야 한다.
- 임시 캡처·빌드 증거는 삭제하지 않고 Git 및 릴리스 입력에서만 제외한다.
- 비밀값과 새 서명 키는 저장소와 소스 아카이브에 들어가지 않는다.

## 의존성과 패치 순서

1. P0: 현재 미커밋 제품 작업을 테스트하고 별도 커밋으로 보존
2. P1: 원격 계약, 기준 태그, 재귀 소스 아카이브, 임시 증거 제외
3. P2: 승인된 제품명·slug·도메인으로 공개 식별자 일괄 전환
4. P3: 라이선스 전문, NOTICE/FORK-NOTICE/SOURCE 화면, SPDX
5. P4: 중국어/GPL 및 미사용 언어 모듈 제거
6. P5: SBOM·비밀값·잔존 식별자·설치/입력/이전 자동 검증
7. P6: 실제 데이터 흐름과 정책 문서·앱 내 고지 대조

P2는 제품명·applicationId·소유 URL 승인 뒤에만 진행한다. P4는 P3의 APK 구성요소
인벤토리가 먼저 있어야 제거 전후 라이선스 표면을 비교할 수 있다.

## 테스트 게이트

- `git diff --check`
- upstream 대비 ahead/behind와 작성자 재검증
- 재귀 submodule 상태와 manifest 해시 일치
- 전체 앱 debug unit test
- 소스 아카이브 생성·해제·SHA-256·금지 경로 검사
- Release 의존성/라이선스 검사
- arm64 APK/AAB 빌드와 merged manifest 검사
- 디바이스 설치, IME 선택, 한글 플러그인 검색, 두벌식 입력
- 공개 식별자 잔존 grep
- 비밀값 정적 검사
