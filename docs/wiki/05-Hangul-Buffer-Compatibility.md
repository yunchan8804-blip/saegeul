# 05. 한글 버퍼 호환 모드 (Hangul Buffer Compatibility)

Android의 일부 앱(자체 렌더링 입력창, 게임 엔진, 원격 데스크톱 등)은 한글의 조합 중 상태(`Composing Text`)를 표준 `InputConnection` 사양대로 처리하지 못해 글자가 겹치거나 뒤바뀌는 문제가 생깁니다. 새글(Saegeul)은 이런 앱을 위해 조합을 키보드 안에서 끝내고 완성된 구간을 한 번에 보내는 **한글 버퍼 호환 모드**를 제공합니다.

이 모드는 기본으로 꺼져 있는 실험 기능입니다. 모든 앱에서 입력을 보장하지는 않으며, 원래 문제가 된 앱에서 전달 방식별로 확인하는 작업은 아직 진행 중입니다.

---

## 1. 문제 원인 및 해결 방식

### 문제 현상
- 조합 처리가 불완전한 입력창에서 한글 `안녕`을 치면 `ㅇㅏㄴㄴㅕㅇ`으로 풀려 입력되거나, 조합 중 커서가 튀는 현상 발생.

### 새글의 해결 메커니즘
새글은 **설정 > 고급 > 한글 버퍼 호환 모드**에서 3가지 전달 방식 중 하나를 고르게 합니다. 어느 방식이 맞는지는 앱마다 다르므로 직접 확인해야 합니다. 한 방식이 실패해도 다른 방식으로 저절로 다시 보내지 않습니다(두 번 입력되는 것을 막기 위해서입니다).

| 모드 | 작동 원리 | 적합한 환경 |
| :--- | :--- | :--- |
| **시스템 붙여넣기 (System Paste)** | 키보드 안에서 완성한 구간을 시스템 클립보드에 넣고 붙여넣기로 보냅니다. 복사해 둔 내용은 사라지고 보낸 글이 클립보드에 남습니다 | 붙여넣기를 받는 일반 입력칸 |
| **Ctrl+V 에뮬레이션** | 같은 방식으로 클립보드에 넣은 뒤 Ctrl+V 키 입력을 보냅니다. 클립보드가 바뀌는 점도 같습니다 | Ctrl+V를 받는 원격 데스크톱·터미널(RDP, AnyDesk, Termux 등) |
| **직접 확정 (Direct Commit)** | 조합이 끝난 구간 전체를 클립보드 없이 `commitText` 한 번으로 보냅니다 | 클립보드를 건드리고 싶지 않을 때, 터미널·게임 채팅창 |

비밀번호·민감 정보 입력칸에서는 고른 방식과 관계없이 직접 확정을 씁니다.

---

## 2. 2단계 엔터(Enter) 확정 계약

버퍼 호환 모드가 켜져 있을 때 엔터 키는 다음과 같이 안전하게 2단계로 분리됩니다:

1. **1회차 엔터:** 아직 보내지 않은 구간을 입력칸으로 보냅니다.
2. **2회차 엔터:** 입력칸에 줄바꿈(NewLine) 또는 메시지 전송(Send) 신호를 보냅니다.

조합 중인 글이 줄바꿈·전송보다 먼저 들어가도록 순서를 지킵니다. 보내기가 확실히 실패하면 글을 버리지 않고 남겨 두었다가 다음 엔터에서 다시 보냅니다. 다만 앱이 붙여넣기를 받았다고 답한 뒤 실제로는 무시한 경우는 키보드가 알 수 없습니다.

---

## 3. 알아 둘 점

- 백스페이스는 아직 보내지 않은 글에서 한 글자씩 지웁니다. 이모지 조합(👨‍👩‍👧), 국기(🇰🇷), 악센트가 붙은 글자도 한 번에 지웁니다.
- 화살표(상하좌우), Home/End, Page Up/Page Down, Tab, Esc, Delete를 누르면 아직 보내지 않은 글을 먼저 보낸 뒤 그 키를 입력칸에 보냅니다. Shift를 함께 누르고 있으면 Shift도 같이 보냅니다.
- 입력칸을 눌러 커서를 옮기거나 앱이 스스로 커서를 옮기면, 글이 엉뚱한 자리에 들어가지 않도록 아직 보내지 않은 글을 버립니다.
- 보내지 않은 글은 메모리에만 있으므로 앱이나 키보드가 강제로 종료되면 사라집니다.
