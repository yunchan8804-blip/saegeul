# 문장 재료 자동 축적

## 범위와 결정

`YunChan/gemma-ondevice-materials`에서 명시적 실험을 지속 가능한 축적 흐름으로 연결한다. 모델·SDK는 Gemma 4 E2B/LiteRT-LM 0.13.1 그대로이며, 현재 디버그 앱의 기능을 완성하는 작업이다. 정식 배포 승격·릴리스 버전 변경은 포함하지 않는다. 기본 팩의 기존 사용자 다운로드 동의 및 즉시 로컬 조회는 유지한다.

전체 문장 생성과 뒷부분 생성 비교 결과에 따라 **문맥 하나마다 전체 문장 2개**를 생성한다. 입력할 때 모델을 호출하거나 개인 금고·실제 입력 내용을 생성 프롬프트로 보내지 않는다. 축적 대상은 기존 비교 실험의 공개된 20개 문맥이다. 임의 사용자 문맥 전체를 학습하거나 항상 추천할 수 있다는 의미가 아니다.

## 확정 계약

- 자동 축적은 기본 꺼짐이다. 사용자가 모델을 준비하고 켠 뒤에만 예약한다. 모델은 APK에 넣지 않으며 다운로드·가져오기는 기존 명시적 동의를 유지한다.
- WorkManager 2.10.5를 debug 의존성으로 추가한다. 고유 반복 작업은 15분 간격이며 충전 중·배터리 부족 아님을 제약으로 둔다. 켜기와 보충 예약은 같은 제약의 고유 일회 작업을 예약한다. 주기는 정확한 실행 시각 보장이 아니다.
- 프로세스 단일 작업 잠금과 기존 `OnDeviceGenerationControl`로 수동·자동 동시 추론을 막는다. 실제 키보드 활성, 충전 해제, 배터리 15% 이하, 메모리 부족, API 29 이상에서 열 상태 MODERATE 이상이면 시작하지 않거나 실행 중 취소한다.
- 한 번에 최대 4개 문맥, 새 요청을 시작할 수 있는 실행 예산은 120초다. 문맥별 목표는 4개, 최대 생성 시도는 6회다. 채워진 문맥은 건너뛰고 부족한 문맥을 우선하며 동일 부족량이면 진행 커서로 순환한다. 취소된 호출은 시도 횟수로 세지 않는다. 소진된 시도는 사용자의 다시 시도 동작으로만 초기화한다.
- 상태는 공개 문맥 번호·진행 커서·시도 수·개수·오류 상태만 영속화한다. 프로세스 재생성 때 과거 실행 중 표시를 그대로 유지하지 않는다. 자동 축적을 꺼도 저장 재료는 유지한다.
- 결과 저장과 끄기는 같은 상태 잠금으로 직렬화한다. 이미 저장 중이던 한 건은 끄기 완료 전에 끝날 수 있지만, 끄기 완료 뒤에는 새 생성 결과를 저장하지 않는다. 코루틴 취소를 네이티브 취소로 전달하고 모델 종료를 기다린다.
- 저장 전 원래 앞부분 일치, 기존 개인정보·문장 형식, 3~12어절, 종결기호, 앞부분 반복·동일 세 어절 반복·문장 중간 종결기호를 검사한다. JSON 코드블록은 기존 은행 규칙과 동일하게 허용한다. 후보별 거부와 중복 수를 기록하고 통과한 후보를 한 번의 원자적 암호화 저장으로 반영한다.
- 이 검사는 모든 한국어 의미·조사 호응을 판정하는 모델이 아니다. 한국어 품질은 별도 원문 검토와 실기기 검증을 유지한다. 형식 통과를 자연스러움 통과로 표시하지 않는다.
- 은행의 기존 상한 2,000개와 1 MiB를 유지한다. 정확한 정규화 문장 중복을 제외하고, 상한 초과 시 선택 횟수가 낮은 문장을 먼저 정리한다. 동률은 오래된 항목부터 정리한다.
- 기존 저장 형식 1에 선택 횟수 `acceptedCount`만 선택 필드로 추가한다. 이전 데이터는 0으로 읽고, 잘못된 값은 거부한다. 선택된 suffix에 대응하는 저장 문장이 단 하나일 때만 횟수를 증가시켜 모호한 문장의 유용성을 부풀리지 않는다. 사용자 원문을 저장하지 않는다.
- 입력 중 조회는 기존 메모리 인덱스만 사용한다. 후보 수락 후 보존 횟수 저장은 application IO scope에서 수행한다.

## 화면

기존 Android 테마·스크롤 화면을 유지한다. 새글 개인정보·AI 설정에서 디버그 전용 '기기에서 문장 재료 쌓기'로 진입한다. 자동 축적 스위치, 지금 보충 예약, 소진된 문맥 다시 시도, 대기·진행·오류, 저장 문장 수와 20개 문맥 중 채운 수를 표시한다. 화면을 나가도 켜 둔 예약은 유지한다. 모델 관리·수동 생성·삭제는 자동 축적을 끈 뒤 수행하며 끄기 조작은 계속 가능해야 한다. 화면 진입 시 모델 전체 해시를 읽지 않는다.

## 검증 게이트

1. 후보별 거부·중복, 저장 실패 보존, 이전 데이터 호환, 선택 횟수 재로드, 상한 정리와 모호한 suffix 방어 단위 테스트.
2. 문맥 선택 공정성·목표 충족·시도 제한·중복 실행·취소와 상태 보존 테스트.
3. debug 앱·AndroidTest 빌드 및 실제 Fold6에서 모델 생성 → 자동 저장 → 중단 → 재로드.
4. 모델을 호출하지 않는 오프라인 추천 표시와 실제 터치 삽입 1초 게이트. 사용자 입력을 가리지 않는 실제 화면 확인.
5. 키보드 시작·축적 끄기·모델 없음·제약 불충족 시 생성 및 저장 경계 확인. 외부 의존으로 실행하지 못한 항목은 통과로 바꾸지 않는다.

## 공식 근거

WorkManager의 제약·최소 15분 반복 주기와 지연 가능성은 [Android 작업 정의 문서](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)에 따른다. 중단과 코루틴 계약은 [CoroutineWorker API](https://developer.android.com/reference/kotlin/androidx/work/CoroutineWorker), 열 상태의 API 경계는 [PowerManager API](https://developer.android.com/reference/android/os/PowerManager)를 확인했다. SDK 35 계열 호환 의존성은 [WorkManager 2.10 릴리스 기록](https://developer.android.com/jetpack/androidx/releases/work#version_210_2)을 기준으로 2.10.5로 고정했다. 확인일은 2026-09-09다.

비공개 설정 파일·logcat 반출 명령은 자동 승인 검토에서 민감정보 위험으로 거부되어 수행하지 않았다. 비개인 테스트 진행 상태와 열 서비스의 상태만 사용했다.

연속 보충 두 번째 검증은 187.879초 후 예약 작업 유휴 전환 180초 제한을 넘겨 실패했다. [WorkInfo 공식 문서](https://developer.android.com/reference/androidx/work/WorkInfo#getNextScheduleTimeMillis())는 가장 이른 예약 시각과 실제 실행 시각을 구분한다. 이 실패를 열 제한으로 단정하지 않고, 테스트에 개별 작업 상태·중단 사유·시도 수와 공개 진행 상태 진단을 추가했다.

세 번째 검증(`device-coverage-r3.log`)은 periodic 작업의 `RUNNING`과 실제 모델 실행을 관측했다. 약 29초에 thermal 상태 `2`와 화면 상태 `기기 온도가 높아 생성을 미룹니다.`를 기록했고, 891.785초에도 같은 상태였다. 테스트는 901.714초에 `Thermal status did not clear before the 900 second coverage deadline`로 실패했다. 이 실행은 예약 경로가 동작함을 보여주지만, 전체 coverage 통과 증거는 아니다. 기기 열 조건을 바꾸거나 검사를 완화하지 않았다. 테스트의 finally는 기존 꺼짐 설정을 복원하고 생성 재료를 보존한다.

### 재개 순서와 완료 조건

1. 현재 ADB 주소를 확인하고 실제 thermal 상태가 MODERATE 미만인 충전 상태에서 진행한다. 키보드 사용·발열 제한을 해제하지 않는다.
2. 아래 coverage 검증을 실행한다. 공개 20문맥 각각 1개 이상 및 재로드 보존이 통과 조건이다. 목표 4개씩 모두 채웠다는 의미는 아니다.
3. coverage와 별도로 기존 오프라인 추천 3문맥에서 표시 1초 이내와 실제 터치 삽입을 모두 통과해야 한다. `오늘 저녁`을 제외하거나 다른 문맥으로 바꾸지 않는다.
4. 전체 문맥의 한국어 자연스러움 검토와 장기간 발열·배터리 관측은 정식 배포 승격 전 추가 게이트다.

모델 없음·충전 해제·저메모리의 실기기 강제 조건 검증과 장기간 배터리 소비 측정은 아직 수행하지 않았다. 전체 임의 문맥 추천 및 한국어 의미 품질의 정식 배포 판정은 이번 디버그 검증 범위 밖이다.
