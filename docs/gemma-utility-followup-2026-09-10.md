# 공개 재료 유용성 후속 개발

상태: 구현·부분 실기기 검증 및 9요청 확장 후 독립 평가 완료. [선행 평가](gemma-input-utility-2026-09-10.md)의 완료 조건 중 후보 유용성 증가를 충족하지 못했다.

## 구현과 검증

공개 순번의 상황·의도·회차를 공용 descriptor로 분리하고 여섯 의도의 의미 지시를 구체화했다. 기존 72조합 순서, 평가 입력 격리, LAST_WORD 제외, 저장 형식·상한과 자원 가드는 유지한다. 정답 예문을 생성 프롬프트에 추가하지 않았다.

기존 평가 24개(완성 전 23개와 경계 1개)를 그대로 유지하고, 별도 공개 합성 held-out 24개를 고정했다. 각 입력과 표본 전체의 SHA-256을 기록한다. 신규 표본은 개발 중 생성 경로에 제공하지 않는 평가 전용 표본이며, 실제 사용자 입력이나 외부 평가자의 비밀 데이터가 아니다. 완성 문장 뒤 공백에서 은행·collect 후보가 나오면 실패한다.

공개 생성 요청마다 실제 응답·요청 의도·첫 두 어절·제외 시작 충돌을 보존한다. 기존 새 터치 후보 검사를 유지하면서, 중복·저장 0개도 측정하는 `measurePublicContextExpansion`을 추가했다. 테스트 성공을 품질 통과로 처리하지 않는다. 입력 중 직접 생성의 별도 [실행 계약](gemma-context-completion-contract-2026-09-10.md)을 정했고 제품 연결은 보류한다.

통합 집중 단위 검사 58개는 실패·오류·스킵 0개다. 앱·테스트 APK 빌드는 `BUILD SUCCESSFUL in 23s`, 종료 코드 0이다. 데이터 유지 설치 후 기존 은행 139개와 공개 순번 1을 확인했다. 첫 빌드의 코루틴 함수·문자열 보간 오류는 수정 후 재검증했다. 전체 단위 테스트나 릴리스 검증을 실행한 결과는 아니다.

| 생성 전 평가 | 노출 | 은행 전후 | 표본 SHA-256 |
| --- | --- | --- | --- |
| 기존 독립 입력 | 0/23 | 139→139 | `08cdc3594bb4659cf42cd7692e15843feffba8cb10b9836d8a8e33227a6427a1` |
| 신규 held-out | 0/23 | 139→139 | `490ae240335949224edcc81dc0c5ead9a684578401fb377da0f862bab3eb91f6` |

각각 `OK (1 test)`, exit 0이며 두 경계도 빈 후보로 통과했다. 자동 준비와 native 생성은 꺼져 있었고 공개 순번은 1로 보존됐다.

## 실제 새 응답의 부분 결과

Fold6에서 순번 0~11을 각 1요청·2문장으로 측정하도록 정했다. 순번 0~8의 9회만 성공했고, 순번 9가 `CancellationException: Task cancelled`와 `FAILURES!!!`로 실패해 중단했다. ADB exit 0은 이 실패를 성공으로 바꾸지 않는다. 순번 10~11은 실행하지 않았다.

성공 로그의 새 응답은 18개, 저장 추가는 16개, 중복 0개, 거부 2개다. 순번별 은행 수는 139에서 155까지 끊김 없이 증가했다. 이 155는 마지막 성공 요청의 수이며, 실패 이후의 최종 재로드 확인값이 아니다. 첫 두 어절 중복은 0/18, 요청별 제외 시작 충돌도 0/18이다. 전체 은행의 시작구절 중복률이나 장기 다양성으로 일반화하지 않는다.

실제 응답의 의도는 요청 문구 기준으로 오케스트레이터가 수동 판정했다. 저장 거부된 응답도 생성 의도 분모에 포함한다.

| 요청 의도 | 준수 | 판정 근거 |
| --- | --- | --- |
| 질문 | 4/4 | 시간·만남·자료 출처·프로젝트 목표에 대한 정보 질문 |
| 요청 | 3/4 | `이거 한번 같이 해봐요?`는 상대 행동 부탁보다 공동 행동 제안으로 판정 |
| 제안 | 4/4 | 함께 식사·산책·대화하는 제안 |
| 상태 전달 | 2/2 | 완료 사실을 전달함. 의미 적합성과는 별도 |
| 확인 | 0/2 | `물건 잘 받았어요?`, `이거 맞죠?`는 일반 사실 확인이지만 이번 지시의 상대 이해 여부 확인은 충족하지 않음 |
| 응답 | 2/2 | 수락·감사·확인 응답 |

엄격한 요청 문구 기준 의도 준수는 15/18이다. 확인을 넓은 사실 확인으로 재정의하면 점수가 달라지므로, 이 수치를 기존 모호한 의도 지시의 결과와 직접 비교하지 않는다. 독립 평가자 합의나 사용자 채택률도 아니다.

`식탁에 설거지를 다 했어요.`는 장소 표현과 서술어의 연결이 어색하다. `이거 한번 같이 해봐요?`는 제안 의도와 질문 종결의 자연스러움을 추가 검토해야 한다. 두 응답 모두 저장 형식 검사는 통과했으므로 저장 성공을 자연스러움으로 계산하지 않는다. `이거 맞죠?`, `감사합니다, 확인했어요.`는 두 어절로 3어절 이상 저장 조건을 충족하지 못해 거부됐다. 이를 통과시키려고 필터를 바꾸지 않았다.

순수 생성 시간은 8.487~13.376초, generator 전체 wall 시간은 12.852~20.880초였다. 입력 중 저장 후보의 조회 시간과 구분한다. 동일 열 상태를 통제한 전후 성능 비교는 아니다.

## 실패와 남은 조건

순번 9 실패 후 기기는 offline이었고 기존 `100.109.125.97:35315` 재연결은 연결 거부(10061), mDNS 검색은 빈 결과였다. 현재 증거만으로 취소 원인을 발열이나 ADB 단절로 단정하지 않는다. 기존 테스트는 실패 시 watchdog 상태를 남기지 않아 원인 구분이 부족했다. 후속 취소 진단에 시작·감지 가드와 native/키보드 상태를 기록하는 보강을 추가했다. 예외 클래스만 기록하고 개인 문장이나 예외 메시지는 별도 evidence에 넣지 않는다. 보강 후 테스트 APK 빌드는 `BUILD SUCCESSFUL in 38s`, 실제 셸 종료 코드 0이며 기기 미연결로 설치·실행하지 못했다.

검증 워커가 도구 호출 완료를 셸 프로세스 종료로 오인한 보고는 반려했다. 이미 실행 중인 루프의 로그를 직접 확인했고, 추가 시도의 파일 리디렉션은 점유 오류로 차단됐다. 순번별 성공 원문과 은행 연속성을 확인해 0~8만 수용했다. 실행 실패나 부분 범위를 숨기지 않는다.

다음 순서는 현재 ADB 주소 확인 → 자동 준비·native 종료·은행 재로드 확인 → 같은 두 utility 메서드 사후 평가다. 두 표본 SHA가 생성 전과 같아야 한다. 추가 생성부터 재시작하지 않는다. 취소 진단 보강 APK의 실기기 확인, 순번 9 실패 원인 확인과 남은 공개 상황 평가도 필요하다. 독립 입력에서 적합한 후보가 증가했는지 확인하기 전 공개 재료 확장 완료로 표시하지 않는다.

증거는 `outputs/gemma-utility-followup-20260910/`의 빌드·설치·생성 전 utility 로그, `expansion-00.log`~`expansion-09.log`, `completed-generation.json`에 보존했다. `summarize.py`는 표본 해시 불일치·절단 로그·실패 로그를 거부하며 수동 의미 판정을 대신하지 않는다. 커밋·push는 하지 않았다.

## 재연결 후 사후 평가

`scripts/measure-gemma-utility.ps1`는 두 utility 검사만 동기식으로 순차 실행한다. 모델 생성·APK 설치·설정 변경·자동 재연결은 하지 않는다. 기존 결과 덮어쓰기와 동시 실행을 거부하고, 각 실행의 ADB 종료 코드·성공 원문·최종 evidence·표본 해시·은행 및 순번 보존을 검사한다. 실패하면 다음 검사를 실행하지 않는다. 의미 적합성은 저장한 후보 원문을 별도로 수동 판정한다.

현재 기기 주소를 확인한 뒤 저장소 루트에서 실행한다. 출력 폴더는 매번 새 이름을 사용한다.

```powershell
./scripts/measure-gemma-utility.ps1 `
  -DeviceSerial '<현재 IP:포트>' `
  -BaselineDirectory './outputs/gemma-utility-followup-20260910' `
  -OutputDirectory './outputs/gemma-utility-followup-20260910/post-resume-01'
```

PowerShell 구문 분석 오류 0과 UTF-8 BOM, 도움말 출력을 확인했다. 공개 순번은 64비트로 보존한다. 출력 폴더의 `.measurement.lock`은 종료 후에도 남겨 재사용을 막는다. 스크립트 추가 당시에는 기기 연결이 없어 실제 ADB 경로가 미검증이었다. 후속 실제 실행 결과는 아래에 기록한다.

## 연결 복구 후 확인

사용자가 제공한 `100.109.125.97:41475`로 연결해 같은 Fold6(`SM-F956N`)를 확인했다. `post-resume-01/`에서 실행기의 두 실제 ADB 평가가 각각 `OK (1 test)`로 끝났고, 은행 155개·공개 순번 1·자동 준비 및 native 생성 비활성·두 표본 SHA 일치를 확인했다. 두 경계도 빈 후보로 통과했다.

| 표본 | 생성 전 139문장 | 9요청 생성 후 155문장 |
| --- | --- | --- |
| 기존 독립 입력 후보 노출 | 0/23 | 0/23 |
| 신규 held-out 후보 노출 | 0/23 | 0/23 |

후보가 없으므로 두 표본의 유용한 첫 후보·상위 3개 유용 후보 비율 역시 0/23이며, 후보별 자연스러움은 평가 불가다. 공개 응답 18개 중 16개 저장은 확인했지만 독립 입력 유용성 증가는 입증되지 않았다. 이전 단절 당시의 생성 취소 원인은 이 재연결만으로 확정하지 않는다.

이후 취소 진단 테스트 APK를 해시 대조 후 데이터 유지 설치했다. 순번 9 재개 첫 명령은 `-e` 키·값을 합친 인자 구성 오류로 계측에 도달하지 못했고, 이를 바로잡은 `expansion-resume-09-corrected.log`는 `OK (1 test)`, 은행 155→157이었다. 새 응답은 `지금 제가 준비한 자료를 보여 드릴게요.`, `회의 준비는 모두 마쳤습니다.`다. 첫 문장은 미래 행동 안내로 상태 전달 지시와 차이가 있고, 둘째는 해요체 지시를 따르지 않았다. 저장 성공을 의도·말투 준수로 계산하지 않는다. 순수 생성 7.785초, generator wall 12.257초였다.

순번 10 시작 시 `device offline`으로 다시 중단했다. `41475` 재연결은 연결 거부(10061)였다. 순번 11과 `post-resume-02`는 실행하지 않았다. 157은 마지막 성공 요청의 수이며, 재단절 뒤 재로드 확인값은 아니다. 따라서 위 0/23 사후 결과는 155문장 시점에만 해당한다.

사용자는 숫자·특수문자 입력 시 거의 멈추는 지연도 보고했다. 별도 입력 경로 조사와 실키 터치 재현을 우선 진행하며, 원인·수정·실기기 지연 개선이 확인되기 전 해결로 표시하지 않는다. 변경 범위와 검증 증거는 [숫자·특수문자 입력 지연 후속 기록](numeric-symbol-input-latency-2026-09-10.md)에 남긴다. 공개 문맥 완성의 제품 연결 보류와 독립 후보 유용성 증가 조건은 그대로 유지한다.

## A35 별도 전후 평가와 다양성 실험

Fold6의 139→155→157 기록과 섞지 않기 위해 A35 `RFCX60GBL3D`의 공개 은행 49개에서 새 baseline을 만들었다. baseline과 확장 뒤 평가는 모두 `generatedPredictions` 기준이며, utility 검사는 각각의 실행 안에서 은행 수와 자동 공개 순번을 보존했다. 자동 준비와 native 생성은 시작·종료 모두 비활성이며, 자동 공개 순번은 26→26이다.

| 표본 | baseline 은행 | 확장 뒤 은행 | 후보 노출 | 유용한 첫 후보 | 상위 3개 유용 후보 | 표본 SHA-256 |
| --- | --- | --- | --- | --- | --- | --- |
| 기존 독립 입력 | 49→49 | 61→61 | 1/23→1/23 | 1/23→1/23 | 1/23→1/23 | `08cdc3594bb4659cf42cd7692e15843feffba8cb10b9836d8a8e33227a6427a1` |
| 신규 held-out | 49→49 | 61→61 | 0/23→0/23 | 0/23→0/23 | 0/23→0/23 | `490ae240335949224edcc81dc0c5ead9a684578401fb377da0f862bab3eb91f6` |

독립 입력의 유일한 후보는 확장 전후 모두 h23 `요즘 어떻게 `에 대한 `지내세요?`이며 전체 문장은 `요즘 어떻게 지내세요?`다. 오케스트레이터 수동 판정에서 의미·조사/어미·띄어쓰기·종결 네 조건을 모두 충족했다. 이전 집계가 독립 입력을 모두 0/23으로 보고한 오류를 instrumentation 원문으로 정정한다. 이 한 후보는 확장 전부터 있었고 held-out에 신규 유용 후보가 없으므로, 공개 재료 확장으로 독립 후보 유용성이 증가했다는 완료 조건은 충족하지 못했다.

확장은 `measurePublicContextExpansion` 6요청으로 140.548초 동안 순번 26~31에서 실행했다. 새 응답 12개가 모두 저장되어 은행은 49→61, 추가 12·중복 0·거부 0이다. 첫 두 어절의 동일 시작은 12개 중 1개(8.3%)이고 요청 당시 제외 시작과의 충돌은 12개 중 3개(25%)다. 이 두 수치는 이번 배치의 응답·요청 시점 기준이며 전체 은행의 시작구절 중복률이나 장기 다양성 비율이 아니다.

| --- | --- | --- |
| 26 · 확인 | `제가 말씀드린 내용 이해하셨어요?` | 통과 |
| 26 · 확인 | `이 부분 확인하셨는지 궁금해요?` | 실패: 상대의 이해 여부 확인이 아님 |
| 27 · 응답 | `네, 그렇게 할게요.` | 통과 |
