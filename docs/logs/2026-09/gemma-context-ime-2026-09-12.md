# 명시 문맥 완성의 IME 연결

상태: debug 명시 IME 연결, 기존·신규 공개 입력 전체의 오프라인 수집·한국어 검토, 취소·세션 변경 회귀 검증을 완료했다. 후보 없음과 한국어 품질 지적은 남아 있으며 release와 자동 입력 중 생성은 활성화하지 않았다.

기준은 `gemma-input-utility-2026-09-10.md`와 `gemma-context-completion-contract-2026-09-10.md`다. 기존 0/23 결과와 공개 은행 조회는 보존한다. 사용자가 에뮬레이터 검증을 요청한 뒤 Fold6 무선 ADB도 연결했다. 오프라인 에뮬레이터와 온라인 실기기 결과를 구분한다.

## 최신 수집 결과

| 입력·경로 | 후보 | IME 표시·터치 적용 | 한국어 엄격 통과 |
| --- | ---: | ---: | ---: |
| 과거 기존 독립 입력, 저장 은행 조회 | 0/23 | 과거 평가 참고 | 후보 없어 평가 불가 |
| 같은 기존 입력, 명시 native 생성, 오프라인 AVD | 20/23 | 20/23 | 나온 후보 20/20 |
| 새 held-out, 명시 native 생성, 오프라인 AVD | 23/23 | 23/23 | 나온 후보 19/23 |

각 입력군의 완성문장 경계 1개는 위 분모에서 제외했으며 native 미시작·후보 없음으로 통과했다. 기존 h15·h22·h23은 원문을 보존한 후보를 얻지 못했다. 저장 은행 조회가 20/23으로 개선됐다는 뜻이 아니다. 새 명시 경로는 공개 은행·개인 금고를 프롬프트로 쓰지 않고 모델이 문맥을 생성한다.

신규 g03·g08·g09는 의미 연결 주의, g23은 의미·어미 실패로 판정했다. g08에는 `고장난` → `고장 난` 띄어쓰기 실패도 있다. [48개 입력별 한국어 검토](gemma-context-quality-2026-09-12.md)에 원문·후보·의미·조사·어미·띄어쓰기·종결형을 분리해 남겼다. 표본을 보고 프롬프트나 후보 후처리를 맞추지 않았다. 이 검토는 오케스트레이터의 직접 언어 평가이며 실제 사용자 채택률이 아니다.

최종 전체 수집은 `emulator-tests/existing-full-03/log`(230.822초)와 `emulator-tests/heldout-full-01/log`(216.275초)에서 각각 `OK (1 test)`다. 모든 후보의 native 종료, 원문 보존, 실제 editor 적용, 중복 적용 거부, 적용 완료 안내, 네트워크 부재, 은행 저장 불변을 검증했다. 후보 표시와 적용 후 PNG도 공개 debug 화면만 수집했다. 완료 지연 중앙값은 각각 5430ms와 5119ms이며 저장 조회의 1초 목표와 혼동하지 않는다.

Fold6 최신 수정본은 `fold6-tests/latest-sample-01/log`에서 `OK (1 test)`다. h01을 실제 IME로 생성·표시·적용하고 성공 안내까지 확인했다(firstText 7312ms, total 8280ms). [실기기 적용 후 화면](../outputs/gemma-context-20260912/fold6-tests/latest-sample-01/public/independent_public_20260910-h01-applied-candidate-110897552.png)을 보존했다. 무선 ADB를 유지한 온라인 실행이므로 오프라인 증거와 합산하지 않는다. 실기기 전체·안전성 수집은 Thermal Status 2로 중단한 기록이 있으며, 가드를 완화하지 않았다.

최신 x86 앱은 `apk-x86_64-build10/`, arm64 앱은 `apk-arm64-final/`에 보존했다. 단위 테스트 35개(개인정보 8, editor transaction 4, context gate 9, completion policy 7, native lease 7)는 failure/error/skip 0이다. x86·arm64 debug 빌드와 release Kotlin 컴파일도 통과했다.

## 안전성 검증 결과

`emulator-tests/safety-02/log`는 65.793초, `OK (1 test)`이며 내부 8개 시나리오가 모두 통과했다. 초기화 취소, decode 중 커서·선택·원문·같은 커서의 원문 변경/복원, 실제 새 email editor 세션 연결, 사용자 취소, 창 닫기에서 native 종료와 후보 폐기·늦은 적용 차단을 확인했다. 세션 변경은 서로 다른 editor 인스턴스·field ID와 실제 새 IME target 연결을 검사하고 이전·새 입력칸을 모두 확인한다. 같은 커서/원문 복원은 무효화 관측 후 복원했으며, 모든 편집기의 초단시간 ABA를 보장한다는 주장은 하지 않는다.

`emulator-tests/public-keyboard-stop-01/log`는 16.859초, `OK (1 test)`다. 공개 준비의 native 실행을 먼저 관측한 뒤 실제 키보드를 열어 중지를 확인했으며 저장 수와 공개 순번은 안정 창에서도 0으로 유지됐다. 명시 생성 예외를 위해 PUBLIC_MATERIAL의 키보드 가드를 해제하지 않았다.

모델 없음 안내, 기존·신규 전체 수집, 8종 무효화는 모두 앱이 관측한 인터넷 네트워크 부재를 검증했다. 비밀번호·민감 입력·개인화 학습 금지·앱 차단 정책은 기존 공통 개인정보 게이트를 거치며 관련 순수 정책 8개 테스트를 통과했다. 각 개인정보 설정 조합에 대한 실제 IME 시험까지 완료했다는 뜻은 아니다.

수집 전체는 앱 `build10`/계측 `test11`, 최종 무효화는 같은 앱과 세션 시험만 고친 `test12`를 사용했다. 앞선 session 시험의 잘못된 버튼 이름으로 인한 실패는 `safety-01`에 보존했다. 최신 테스트에서 실제 버튼·새 editor를 확인하도록 바로잡았으며 본문 안전성 assertion과 30초 native 종료 제한은 유지했다. 네트워크와 원래 IME는 복원했고 `emulator-tests/final-restoration.txt`에 기록했다.

## 남은 범위

- 기존 h15·h22·h23의 후보 없음, 신규 g03·g08·g09·g23의 한국어 지적을 남긴다. 다음 모델·프롬프트 개선 시에는 이번 held-out을 개발 표본으로 분류하고 새 독립 표본을 먼저 고정해야 한다.
- 짧은 문맥은 의도를 충분히 정하지 못하며, 상투적이거나 새로운 사실을 가정한 완성이 나올 수 있다. 현재 후보를 자동 확정하거나 입력 중 자동 실행하지 않는다.
- 실기기는 최신 공개 입력 1개의 수집·표시·적용을 확인했다. 실기기 전체 표본과 취소 8종은 발열 차단으로 완료하지 못했으며 에뮬레이터 통과와 구분한다.
- 모든 편집기의 모니터 계약 준수, release용 모델 설치·배포·제품 활성화는 이번 검증 범위가 아니다. 현재 구현을 출시 완료로 판단하지 않는다.

## 확정한 경계

- 기존 AI 패널에서 별도 명시 동작으로 문맥 완성을 연다. 원문을 먼저 보여주고 사용자가 실행을 눌러야 모델에 전달한다. 자동 입력·공개 재료 조회에 모델 생성을 끼워 넣지 않는다.
- 최초 연결은 기존 모델과 native 의존성이 있는 debug에서만 제공한다. release 활성화는 한국어 적합성·오프라인·취소·편집기 적용 검증 이후 별도 판단한다.
- AI 도구 버튼은 debug 로컬 기능의 개인정보·앱 정책 조건을 만족해도 열 수 있다. 외부 AI 실행의 네트워크 차단은 그대로 유지한다. 로컬 진입까지 외부 AI의 네트워크 조건에 묶지 않는다.
- 최초 지원 범위는 커서가 문맥 끝에 있고 선택 영역이 없는 미완성 입력이다. 선택 영역이나 중간 커서는 안내 후 거부하며 임의로 이동하지 않는다. 문맥은 최대 2048자다.
- 검토한 문맥만 메모리에서 처리한다. 공개 은행·개인 금고·클립보드를 프롬프트에 합치거나 원문·응답을 로그에 저장하지 않는다. 외부 공급자 fallback은 없다.
- 모델은 원문을 그대로 앞에 보존한 완성 문장을 생성한다. 원문 불일치·빈 접미부·형식 위반은 후보 없음으로 남긴다. 생성 결과의 접두부 확인은 원문 보존 검사이며 저장 은행의 prefix 조회가 아니다. 형식 통과를 의미·문법 통과로 취급하지 않는다.
- `PUBLIC_MATERIAL`은 키보드 활성 중 거부·취소한다. 사용자가 누른 `EXPLICIT_CONTEXT`만 기존 목적별 단일 native lease를 사용한다. 배터리 20% 이상, 절전 아님, 메모리 여유, 확인 가능한 열 상태가 MODERATE 미만인 조건을 시작과 실행 중 검사한다.
- 입력·커서·선택·세션 변경, 화면 종료, 사용자 취소는 ticket을 무효화하고 해당 native run을 취소한다. 변경 후 원래 값으로 돌아와도 이전 요청을 살리지 않는다. 늦게 도착한 결과는 폐기한다.
- 명시 캡처 때 `GET_EXTRACTED_TEXT_MONITOR`로 텍스트 변경 알림을 요청한다. 초기 전체 원문·선택 범위를 확인할 수 없는 편집기는 거부한다. 해당 요청 token의 `onUpdateExtractedText`는 값이 원복됐더라도 요청을 무효화한다. 커서 이벤트와 100ms 조회는 보조 수단이다. Android는 원문 변경 시 selection callback을 생략할 수 있으므로 selection callback만으로 입력 변경을 보장하지 않는다. 편집기가 Android의 모니터 계약을 준수해야 한다는 제한은 남는다. [Android InputMethodService 계약](https://developer.android.com/reference/android/inputmethodservice/InputMethodService#onUpdateSelection(int,%20int,%20int,%20int,%20int,%20int)).
- 생성 제한 120초와 취소 후 native 종료 확인 제한 30초를 구분한다. 종료 미확인 시 다음 추론을 차단한다. 결과 적용은 native 종료와 원문 재검증 후 한 번만 소비하며 실제 editor 변경 확인까지 있어야 적용 성공이다.

## 평가 계획과 고정 표본

새 공개 합성 표본은 모델 응답을 보기 전에 23개 미완성 입력과 완성문장 경계 1개로 고정했다. 파일은 `app/src/androidTest/assets/gemma-context-heldout-20260912.json`, SHA-256은 `043ec620e8cd8e0bc006fce0dc9a42f9ecf2e1dba007da8ce81acb3fd164c6b5`다. 정답 문장은 없다. 공개 재료 생성이나 은행에는 제공하지 않고 명시 문맥 완성 평가의 요청 입력으로만 사용한다.

기존 독립 표본과 신규 표본은 각각 분모를 유지한다. 은행 조회의 과거 0/23과 명시 native 생성 결과는 서로 다른 경로·지연이라는 점을 표시한다. 각 입력에서 후보 존재, 실제 IME 표시, 터치 적용, 적용 후 원문을 따로 보존한다. 공개 합성 원문만 평가 증거에 기록한다.

한국어 수동 평가는 의미·주체·조건, 조사와 어미, 띄어쓰기, 종결형을 각각 판정한다. 후보 없음은 유용한 제안 없음으로 세지만 후보별 자연스러움은 평가 불가다. 계측 테스트 통과는 수집 계약 통과일 뿐 품질 성공이 아니다.

네트워크는 Wi-Fi·모바일 데이터 차단과 앱의 인터넷 네트워크 부재를 실제 확인한다. 검증되지 않은 인터넷 연결을 오프라인이라고 간주하지 않는다. 모델 없음·실행 오류·취소 경쟁·원문/커서/선택/세션 변경·중복 적용을 별도로 검사한다. 에뮬레이터의 ABI가 실제 native 라이브러리와 맞지 않으면 실패 근거를 남기고 모델 실행 성공으로 대체하지 않는다.

사용자가 이후 Fold6 무선 ADB도 연결했다. 에뮬레이터는 `requiresOffline=true`로 네트워크 차단을 검증하며, 무선 연결을 유지하는 실기기 수집은 명시적 `requiresOffline=false`와 `offlineProof=false`로 기록한다. 온라인 실기기의 로컬 생성·IME 증거를 오프라인 증거에 합산하지 않는다. 기본값은 계속 `true`이며 다른 인자 값은 오류다. 기기의 배터리·발열 가드는 환경에 관계없이 유지한다.

## 변경 보존과 UI

기존 dirty 변경을 보존하고 관련 파일은 수정 전 사본과 비교한다. 커밋·push·버전 변경은 하지 않는다. UI는 기존 Android IME 패널의 테마·버튼·스크롤 규칙을 따른다. 미확정 생성 시간에 임의 진행률이나 남은 시간을 표시하지 않는다.

계측은 실제 시스템 IME 재바인딩, 도구막대 열기·스크롤, 보이는 버튼 터치를 사용한다. 테스트 시작으로 기존 IME 프로세스가 종료될 수 있으므로 재바인딩 후 실제 서비스와 에디터 연결을 각각 확인한다. 원래 IME와 자동 공개 준비 설정은 종료 시 복원하며 복원 실패도 기록한다. 수동 공개 준비 요청이 남아 있으면 이를 없애지 않고 테스트를 거부한다.

공개 은행의 `load()`는 내용이 같아도 메모리 revision을 올린다. 따라서 은행 불변 여부는 저장 파일의 존재·크기·SHA-256과 문장 수로 검증하고, revision은 재조회에 영향을 받는 관측값으로만 남긴다. 정리 중 오류가 본문 오류를 가리지 않도록 원본 예외와 정리 오류를 함께 보존한다.

공유 에뮬레이터의 사후 화면은 IME 증거로 사용하지 않는다. 전용 AVD `SaegulGemma_Isolated_20260912`를 `emulator-5580`으로 실행한다. 실패 화면도 정리 전에 공개 입력용 debug Activity가 앞에 있는지 확인한 경우에만 수집한다.
