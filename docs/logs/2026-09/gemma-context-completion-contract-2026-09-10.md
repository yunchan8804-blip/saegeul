# 온디바이스 문맥 완성의 실행 계약

상태(2026-09-12 갱신): debug의 명시 IME 문맥 완성 연결을 구현하고 오프라인 에뮬레이터의 전체 공개 표본, 실기기의 공개 입력 1개 표시·적용, 취소·무효화 계약을 검증했다. 후보 없음과 한국어 품질 지적은 남아 있다. release 및 자동 입력 중 생성은 활성화하지 않았다. 최신 구현 경계와 실행 결과는 [IME 연결 검증](gemma-context-ime-2026-09-12.md)을 따른다. 아래 하위 구현·기기 증거 기록은 2026-09-10 당시 상태이며 후속 검증 완료를 뜻하지 않는다. 공개 은행 조회와 입력 중 모델 완성은 서로 다른 실행 경로다. [독립 입력 평가](gemma-input-utility-2026-09-10.md)의 저장 조회 0/23은 보존하며 새 명시 경로의 성과로 대체하지 않는다.

## 데이터 경계

공개 재료 준비는 공개 상황·의도·공개 은행의 최근 시작구절만 입력으로 받는다. 평가 fixture, 실제 입력, 개인 금고, 클립보드, 다른 앱 화면을 전달하지 않는다. 평가 표본을 정답으로 저장하지 않는다. 기존 LAST_WORD 제외와 저장 제한을 유지한다.

문맥 완성 실험은 별도 디버그 명시 실행으로만 시작한다. 최초 검증은 공개 합성 입력만 쓴다. 이후 개인 입력 지원은 현재 편집기의 사용자가 명시적으로 선택한 문맥만 메모리에서 처리하며 공개 은행·로그·평가 파일에 저장하지 않는 경계 검증을 통과해야 한다. 개인 금고와 공개 은행을 자동으로 프롬프트에 합치지 않는다. 외부 공급자 fallback은 없다.

## 실행과 취소

요청은 requestId, editorSessionId, 원문과 커서·선택 범위의 스냅샷을 갖는다. 상태는 대기 → 실행 → 결과 준비 → 적용 또는 취소/실패다. 입력 변경, 커서·선택 변경, 편집기 교체, 화면 종료, 사용자 취소, 자원 조건 위반은 요청을 무효화한다. 무효화 이후 도착한 native 결과도 폐기한다. 새 요청은 이전 native 종료가 확인된 뒤 시작한다.

현재 OnDeviceGenerationControl은 키보드 활성 시 공개 재료 생성을 거부·취소한다. 이 가드를 해제해 문맥 완성을 끼워 넣지 않는다. 공개 준비와 명시적 문맥 완성이 같은 단일 native 소유권을 공유하되 각 요청의 종료만 자신의 소유권을 해제하는 조정 계약은 구현했다. 활성 키보드 예외는 명시 요청에만 적용하고 백그라운드 준비는 계속 금지한다. 현재 production 호출 경로는 명시 문맥 목적을 획득하지 않는다.

### native 소유권 구현 계약

소유권은 외부에서 만들 수 없는 불투명 `Lease`로 표현한다. `PUBLIC_MATERIAL` 요청은 기존 키보드 차단·취소를 유지하고, `EXPLICIT_CONTEXT` 요청만 키보드 활성 상태에서 소유권을 얻을 수 있다. 두 목적은 동시에 실행할 수 없다. 기존 생성 호출의 기본 목적은 공개 재료이며 명시 문맥 경로를 자동 활성화하지 않는다. 해제는 발급한 단일 lease의 동일성으로만 한 번 가능하다.

해제에는 발급받은 lease가 필요하고 현재 소유자와 일치할 때만 성공한다. 이전 요청의 늦은 해제나 중복 해제가 새 요청의 소유권을 지울 수 없다. 취소 callback과 외부 취소는 생성기 전체가 아닌 해당 run에 고정한다. 취소 flag는 결과 publish 전까지 보존한다. 취소 요청은 소유권 해제가 아니며 native 대화와 엔진 close가 모두 성공한 뒤에만 lease를 해제한다. 둘 중 하나라도 close에 실패하면 오류를 전파하고 lease를 유지하여 새 추론을 차단한다. 이 소유권 기반 구현만으로 세션·선택·원문 변경 검증이나 제품 연결 조건이 충족되는 것은 아니다.

결과 적용 직전에 세션·원문·커서·선택 범위를 다시 검사하고 한 번만 적용한다. 불일치는 적용 거부이며 대체 삽입을 하지 않는다. 취소 UI 응답과 native 종료 시간을 분리해 측정한다. native 종료가 30초 이내 확인되지 않으면 해당 실험은 실패로 기록하고 추가 생성을 중단한다.

### 순수 문맥 완료 gate 구현 계약

`OnDeviceContextCompletionGate`은 비어 있지 않고 2048자 이하인 `Snapshot(session, text, start, end)`만 받으며 범위를 검사한다. 발급 ticket은 private identity이고 상태는 `RUNNING`에서 `READY`를 거쳐 `takeForApply`로만 이동한다. 취소하면 payload 참조를 즉시 제거하되 native가 멈출 때까지 slot을 점유한다. native 종료 뒤에도 같은 snapshot에 대해서만 결과를 한 번 소비할 수 있고, 이전 ticket은 새 run의 publish·cancel·end에 영향을 주지 않는다. `takeForApply`의 소비 권한은 실제 editor 적용 성공을 뜻하지 않는다.

이 gate는 순수 상태 계약이다. 기존 `AiInputSnapshot`과 target의 연결, 실제 editor 무효화, native 취소 통합은 아직 구현되지 않았다. 따라서 session·원문·커서·선택 변경 뒤 실제 editor에 늦은 결과가 적용되지 않는다는 제품 수준 증거는 아직 없다.

## 측정과 제품 연결 조건

공개 확장 실험은 생성 전후 같은 기존 표본과 별도 신규 held-out 표본을 조회한다. 표본은 생성 전에 고정하고 SHA-256을 보존한다. 신규 표본도 공개 합성 평가 입력이며 실제 사용자 채택률이 아니다. 노출률과 수동 의미·조사/어미·띄어쓰기·종결 판정을 분리한다. 표본 수정 후의 수치를 이전 동일 표본 비교로 제시하지 않는다.

새 응답의 첫 두 어절 중복률은 `(응답 수 - 고유 시작 수) / 응답 수`로 기록한다. 제외 시작 충돌률은 요청별 실제 제외 목록과 비교하며 전체 은행 중복률이라고 부르지 않는다. 의도 준수율은 요청 의도와 실제 문장을 함께 수동 판정하고 형식 통과율과 분리한다.

문맥 완성은 준비·첫 응답·완료·취소·native 종료 지연, 메모리와 열 상태를 기록한다. 기존 1초 목표는 저장 재료 표시 목표이며 모델 생성 완료 목표로 바꾸지 않는다. 관측 지연에 맞는 사용자 경험을 결정하기 전 자동 입력 경로에 연결하지 않는다. 실제 네트워크 차단 상태에서 성공과 모델 없음·오류 동작을 확인해야 하며, 오프라인이라고 단순 선언하는 것으로 통과하지 않는다.

제품 연결은 독립 입력 수동 적합성, 취소 경쟁, 세션 변경 후 늦은 결과 폐기, 정확히 한 번 적용, 실제 오프라인 실행, 자원 제한 보존 증거를 모두 갖춘 후 별도 판단한다. 이 문서 작성과 공개 재료 평가 구현만으로 그 조건을 완료 처리하지 않는다.

`firstTextMs`는 run 시작부터 모델 검증·초기화를 포함해 첫 non-empty `Content.Text`를 받을 때까지 측정한다. whitespace를 포함한 실제 text 기준이므로 첫 의미 토큰 시간이 아니며, 관측하지 못하면 `null`이다.

## native lease 구현과 검증

`OnDeviceGenerationControl`에 `PUBLIC_MATERIAL`과 `EXPLICIT_CONTEXT` 목적을 두고, 외부에서 만들 수 없는 단일 불투명 lease와 동일성 기반 해제를 구현했다. 공개 목적은 기존 키보드 가드를 유지하고 명시 목적만 키보드 활성 상태에서 허용한다. 현재 production 호출 경로에는 `EXPLICIT_CONTEXT` 획득이 없어 제품 문맥 완성은 연결되지 않았다.

각 generator run은 자신의 취소 callback과 외부 취소에만 묶인다. 결과 publish 전에 취소 flag를 다시 확인하며, native 대화 close와 엔진 close가 모두 성공해야 lease를 반납한다. close 실패에는 lease를 남겨 다음 추론을 차단한다.

첫 구현은 private constructor 경계의 컴파일 실패가 있었고, sealed interface와 private 구현으로 경계를 고친 뒤 `:app:testDebugUnitTest --tests '*OnDeviceGenerationControlTest' :app:compileDebugKotlin`을 통과했다. `verify-02.log`는 7개 통과, failure/error/skip 0, `BUILD SUCCESSFUL in 1m 11s`, 종료 코드 0이다. arm64 앱·계측 APK 빌드도 `build-arm64.log`에서 `BUILD SUCCESSFUL in 1m 2s`, 종료 코드 0이다.

아티팩트는 `.artifacts/gemma-native-lease-20260910/`에 보존했다. arm64 앱 SHA-256은 `DA79C4DB66A891466AF2686F89CCE8181D2770D587CC37CFF67B91B53A2894B4`, 계측 APK SHA-256은 `83B28852DC8F63AF255A665B963379167037BEAFB6FD6FD117C8923B2D2A4DD4`다. A35 키보드 취소 회귀는 같은 아티팩트의 `a35-keyboard-stop.log`에서 `OK (1 test)`, 24.858초로 끝났다. 키보드 표시 전 native 실행 관측과 표시 뒤 native 중지가 모두 `true`였고, 저장 수 61과 공개 순번 26은 2초 안정 창에서도 유지됐다. 이 2초 안정 창은 저장 수와 순번이 더 변하지 않는지 확인하는 관측 구간이며, native 종료를 확인하는 30초 제한을 대체하거나 완화하지 않는다.

requestId·editorSessionId·현재 원문·커서·선택의 재검증과 무효화, 늦은 결과 폐기, 정확히 한 번 적용, 실제 오프라인 문맥 응답, 수동 한국어 적합성 검증은 아직 구현·제품 연결 완료가 아니다. 따라서 이 native lease 구현은 원래 공개 재료 유용성 목표나 문맥 완성 제품 연결의 완료 판정이 아니다.

## 순수 gate 검증과 다음 실기기 범위

`.artifacts/gemma-context-completion-20260910/unit.log`와 test XML은 `OnDeviceContextCompletionGateTest` 9개, `OnDeviceGenerationControlTest` 7개로 총 16개가 failure/error/skip 0임을 보인다. 같은 실행의 `:app:compileDebugKotlin`은 `BUILD SUCCESSFUL in 49s`, 종료 코드 0이다. 이는 순수 상태·lease 계약 검증이며 실제 device 검증은 아니다.

다음 실기기 검증은 공개 합성 문맥 3개를 raw `EXPLICIT_CONTEXT` CPU 요청으로 실행한다. 공개 은행에는 저장하지 않으며, 실제 Wi-Fi와 모바일 데이터가 모두 꺼진 상태에서 실행·모델 없음·오류 동작을 확인할 예정이다. 이 계획은 실제 오프라인 실행 증거가 아니다.
