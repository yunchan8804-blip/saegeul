# 공개 생성 후보의 독립 입력 평가

후속(2026-09-12): 이 문서의 저장 은행 조회 0/23은 당시 평가 결과로 보존한다. 별도로 구현한 명시 native 문맥 완성의 후보 존재·IME 표시·적용·한국어 품질은 [IME 연결 검증](gemma-context-ime-2026-09-12.md)과 [입력별 품질 평가](gemma-context-quality-2026-09-12.md)를 따른다. 두 실행 경로의 결과와 지연을 합산하지 않는다.

## 평가 계약

기존 생성 결과를 본 뒤 그 문장의 앞부분만 넣으면 검색 성공을 과대평가한다. 이번 평가는 생성 프롬프트에 넣지 않은 공개 합성 입력 23개와 완성 문장 경계 1개를 고정하고, 현재 기기에 저장된 공개 생성 은행만 읽는다. 실제 사용자 입력·개인 금고는 사용하지 않는다. 평가 입력을 새 문장 생성에 제공하거나 은행에 추가하지 않는다.

일정·이동·식사·집안일·구매·협업·학습·취미·컨디션·방문·감사·안부의 12영역을 포함한다. 문장 생성으로 확인한 시작 구절 3개는 조회 경로의 양성 대조군이며 독립 평가 분모에 넣지 않는다. 완성 문장 뒤 공백 입력은 빈 후보를 기대하는 경계 검사로 분리한다.

측정은 공개 은행 `complete(prefix, 3)`의 후보와 순위, 매칭 근거, 결합 방식, 조회 시간이다. 같은 입력에 `ImmediateContextualPredictions.collect`의 공개 생성 조회만 연결한 후보도 별도 수집한다. 은행 API부터 마지막 한 어절만 일치하는 `LAST_WORD`를 제외하며, collect 경로는 표시 가능 문자와 중복 등을 추가로 검사한다. 유용성 분모의 후보는 collect 결과를 사용하며 은행 조회는 원인 분석용으로 남긴다. 실제 IME의 전체 후보 통합·화면 표시·터치·개인화 성능과 구분한다. 생성 은행 하나의 결과를 앱 전체의 정확도라고 부르지 않는다.

## 판정 기준

- 후보 노출률: 완성 전 입력 23개 중 후보가 하나 이상 나온 입력의 비율.
- 유용한 첫 후보 비율: 23개 중 첫 후보가 아래 네 조건을 모두 만족한 입력의 비율. 후보 없음은 유용한 제안 없음으로 센다.
- 상위 3개 유용 후보 비율: 23개 중 최소 하나가 네 조건을 모두 만족한 입력의 비율.
- 후보 적합성: 앞부분의 의미·주체·조건에 자연스럽게 이어지는가, 조사·어미가 호응하는가, 띄어쓰기가 자연스러운가, 종결형이 자연스러운가를 각각 기록한다. 의미를 억지로 보완해야 하는 문장은 통과시키지 않는다.
- 경계 검사: 이미 완성된 문장 뒤 공백에서 후보가 나오지 않아야 한다.

의미 평가는 오케스트레이터의 수동 판정이며 독립 한국어 평가자의 합의나 실제 사용자의 채택률이 아니다. 작은 합성 표본이므로 일반 입력 전체로 수치를 일반화하지 않는다. 원문과 판정을 보존해 재검토할 수 있게 한다.

## 원인과 다음 개발 조건

현재 `GeneratedSentenceBank.complete`는 저장한 문장의 접두부나 이어지는 어절이 문자 그대로 일치하는 검색이다. `SentencePackIndex`는 접두부, 문맥 뒤쪽 두 어절 이상, 마지막 단어 순으로 찾지만 생성 은행은 마지막 단어만 맞는 결과를 제외한다. 이는 의미가 비슷한 새 입력을 모델이 이해하고 완성하는 경로가 아니다. 139개 은행과 이 검색 방식의 조합이 이번 독립 입력을 덮지 못했다. 검색 범위 밖의 문장을 더 많이 생성하는 것만으로 얼마나 해결되는지는 아직 측정하지 않았다.

적중률을 맞추려고 평가 입력을 생성 프롬프트에 넣거나 은행에 정답으로 추가하지 않는다. 마지막 단어만 맞는 후보를 허용하는 변경도 이번 결과로 정당화되지 않는다. 불필요한 후보가 아니라 유용한 후보를 늘려야 한다.
