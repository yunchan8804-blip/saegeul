# Gemma 전체 문장·뒷부분 생성 비교

## 가설과 고정 조건

현재 실험 브랜치에서 같은 Gemma 4 E2B와 LiteRT-LM 0.13.1을 사용한다. 앱이 입력 앞부분을 고정하고 모델은 뒷부분만 생성하면, 전체 문장을 다시 생성시키는 것보다 입력 문맥에 사용할 수 있는 후보가 늘어나는지 확인한다. 문장 자연스러움 개선은 별개의 가설이며 앞부분 고정만으로 보장하지 않는다.

- Fold6 CPU, 동일 모델 파일·샘플러 기본값·토큰 상한을 사용한다.
- 고정 문맥 20개마다 FULL(전체 문장), SUFFIX(뒷부분)를 각각 한 번 호출한다. 한 호출에서 JSON 문자열 2개를 요청한다. 총 40회·요청 후보 80개다.
- 홀수 문맥은 FULL 먼저, 짝수 문맥은 SUFFIX 먼저 실행한다. 매 호출 모델 생성·종료 계약을 유지한다.
- FULL은 모델이 만든 전체 문장을 그대로 평가한다. SUFFIX는 앱이 보관한 앞부분에 응답을 연결한다. 양쪽 모두 응답 양끝 공백만 제거하고, 조사 교체·접두부 제거·문장 교정은 하지 않는다.
- SUFFIX가 앞부분을 반복하면 실패로 기록한다. JSON 실패·중복·기존 문장 형식/개인정보 검사 거부도 기록한다. 모델 원문을 성공 응답으로 대체하지 않는다.
- 사용자 입력·개인 금고·기존 생성 은행을 읽거나 바꾸지 않는다. 각 호출의 검증에는 별도 임시 암호화 은행을 사용한다.

## 평가 기준

1. **표면 조건과 조회:** 입력 앞부분 보존, 형식 검사 통과, 실제 은행 조회에서 후보가 1개 이상인 문맥 수/20, 고유 후보 수.
2. **한국어 품질:** 오케스트레이터가 실제 원문을 읽고 조사·어미·띄어쓰기·문맥 적합성을 평가한다. 형식 검사 통과를 자연스러움 통과로 간주하지 않는다.
3. **사용 가능한 결과:** 표면 조건과 한국어 품질을 모두 충족한 후보가 있는 문맥 수를 비교한다. SUFFIX가 이 수를 늘리고 어색한 결과 비율을 악화시키지 않는지 본다.
4. **시간:** 초기화·생성·전체 호출 시간을 구분한다. 전체 호출에는 모델 무결성 확인과 종료가 포함된다. 키보드 표시 지연으로 해석하지 않는다.

이는 20개 문맥을 이용한 소규모 탐색 실험이다. 반복 표본·블라인드 다인 평가가 없으므로 일반적인 한국어 성능 우위나 통계적 유의성을 주장하지 않는다. 벤치마크 실행 완료와 가설 채택은 별개다.

## 상태

2026-09-09 Fold6(SM_F956N, CPU)에서 40회 생성과 같은 원문 40건의 재생 검증을 완료했다. **이번 조건에서는 뒷부분만 생성하면 사용 가능한 후보가 늘어난다는 가설을 채택하지 않는다.** 이 방식의 제품 적용은 보류한다.

## 검사 조건 보완과 관측 결과

첫 검사는 응답 전체를 `JSONArray(raw.trim())`로 읽었다. 모델 응답 40개가 모두 JSON 코드블록으로 감싸져 있어 양쪽 모두 형식 통과와 조회가 0이었다. 이 엄격한 원본 결과를 그대로 보존했다. 실행 중 확인한 기존 `GeneratedSentenceBank.stripJsonFence`는 일반 코드블록과 json 코드블록을 허용하므로, 원본 실행을 끝낸 뒤 **동일 원문에 대한 별도 사후 재생 검사**를 추가했다. 새 추론, 문장 교정, 앞부분 제거, 종결기호 보충은 하지 않았다. 따라서 아래 수치는 최초 엄격한 검사 결과를 대체하지 않는다.

재생은 코드블록 포장만 기존 은행과 같은 규칙으로 제거한 후 각 후보를 실제 임시 암호화 은행에 저장·재로드·조회했다. 후보별로 독립 검증하며, 실제 화면의 일괄 저장이나 키보드 터치 E2E를 검증한 것은 아니다.

| 같은 생성 원문에 대한 재생 지표 | FULL | SUFFIX |
| --- | ---: | ---: |
| 형식 통과 호출 | 20/20 | 20/20 |
| 저장 검사 통과 후보 | 36/40 | 26/40 |
| 조회 후보가 있는 문맥 | 18/20 | 13/20 |
| 앞부분 전체 반복으로 거부한 후보 | 0/40 | 10/40 |
| 한국어 적합 판정 후보(형식과 별도) | 36/40 | 17/40 |
| 저장·앞부분 조건과 한국어 적합을 함께 충족한 후보 | 32/40 | 14/40 |
| 위 후보가 있고 실제 조회도 성공한 문맥 | **18/20** | **9/20** |

보류 판정은 사용 가능한 후보에 포함하지 않았다. SUFFIX의 `조금 늦을 것 늦을 것 같아요.`처럼 앞부분 일부만 반복한 경우는 단순 전체 접두부 반복 검사에서 걸러지지 않는다. `오늘은 몸이 좋은 하루 보내세요.`도 저장·조회는 통과한다. 이는 표면 형식 검사만으로 한국어 호응을 보장할 수 없다는 실제 사례다. 최초 엄격한 검사에서 parsed output이 0인 것은 생성 후보가 없다는 뜻이 아니라 코드블록 포장 단계에서 거부됐다는 뜻이다.

## 시간과 해석

| 20회 호출의 중앙값 | FULL | SUFFIX |
| --- | ---: | ---: |
| 모델 초기화 | 528.5ms | 531ms |
| 2개 후보 생성 | 2,958ms | 2,566ms |
| 전체 호출(무결성 확인·종료 포함) | 7,241ms | 6,889ms |

40회 생성 테스트는 294.997초, 원문 재생 테스트는 30.1초였으며 각각 `OK (1 test)`로 끝났다. 두 테스트의 통과는 수집·실행 계약의 통과이지 문장 품질 통과가 아니다. 입력 시점의 1초 목표는 이번 생성 경로에서 달성하지 못했다. 키보드 표시 지연은 이번 비교에서 측정하지 않았다.

**결정:** 입력 중에는 저장한 문장을 로컬 조회하고, 생성은 사전에 수행한다는 방향을 유지한다. 현 모델·프롬프트에서 SUFFIX 방식의 제품 적용은 보류한다. 이번 FULL은 한 호출에 문맥 하나와 후보 두 개를 요청했다. 이전 여러 문맥을 한꺼번에 요청한 실험과 조건이 다르므로 향상을 인과적으로 단정하지 않는다. 다음 저비용 실험 후보는 전체 문장을 한 문맥씩 요청하는 방식의 반복성 확인이며, 이번 변경으로 기존 화면의 기본 생성 프롬프트를 교체하지 않았다.
