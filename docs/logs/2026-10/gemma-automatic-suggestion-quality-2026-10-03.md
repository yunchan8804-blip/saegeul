# Gemma 자동 문장 추천 — 문맥·품질·속도 개선 (2026-10-03)

에뮬레이터(`SaegulGemma_Isolated_20260912`, CPU 4스레드)와 실기기 A35(`RFCX60GBL3D`, GPU)에서 측정하고 고쳤다. 설계 결정은 오케스트레이터가 실측을 근거로 내렸다.

## 측정 도구

- `GemmaSuggestionQualityDeviceTest`: 따뜻한 엔진에 고정 공개 시나리오 20개(`androidTest/assets/gemma_quality_scenarios.json`)를 넣어 프롬프트·원응답·파싱 결과·지연을 `files/gemma-quality/results-latest.json`에 남긴다. `-e templateFile`로 프롬프트 변형을 재빌드 없이 비교할 수 있다(치환자 `{META} {APPTYPE} {HINT} {RECENT} {STYLE} {TEXT} {PREV} {CUR}`). 품질 판정은 사람이 한다.
- `GemmaAutomaticImeTypingDeviceTest`: 실제 새글 IME에 어절 단위(250ms 간격)로 입력하고 후보 칩이 보일 때까지 지연·후보·실제 프롬프트를 `ime-results-latest.json`에 남긴다. 차가운 엔진은 키보드가 숨겨져야 웜업하므로 켠 뒤 한 번 숨겼다가 다시 띄운다.

## 확정 설계 (`OnDeviceSuggestionPolicy`)

1. **전체 문장 완성 방식**: 앞 내용(완결 문장)과 쓰는 중인 문장을 나누고, 모델이 쓰는 중인 문장을 끝까지 다시 쓰게 한 뒤 앱이 그 앞부분을 뗀다. 2026-09-09 비교 실험(FULL 36/40 vs SUFFIX 17/40)과 같은 결론이다.
2. **프롬프트 예산 190자**: 지시문과 쓰는 중인 문장(60자 상한)이 필수이고, 말투→앱→앞 내용 꼬리(80자)→입력창→비슷한 글 순으로 예산 안에서만 넣는다. JSON 메타·따옴표는 쓰지 않는다.
3. **말투 판별**: 앞 문장·최근 보낸 문장의 끝말(요/니다 vs 어/아/야…)과 높임 표지(하신·드리…)로 존댓말/반말을 정하고, 동률이면 업무·메일 앱은 존댓말로 둔다.
4. **"최근 보낸 글"은 프롬프트에 넣지 않는다**: 작은 모델이 그대로 베껴 이전·다른 대화의 문장이 새 문장에 섞였다(IME E2E 실측). 최근 문장은 말투 판별에만 쓴다.
5. **비슷한 글 예시는 입력 중인 글에 이미 들어 있으면 뺀다**: 방금 완성한 문장이 금고에 기록돼 가장 비슷한 예시로 되돌아왔다.
6. **지시문 "짧게 끝맺어"**: A35에서 출력 최대 51→41자, 최대 지연 3.7→3.0초.
7. **파서**: `**`·따옴표 장식 제거, 앞 문장을 바꿔 말한 되풀이 거부(공통 부분 문자열 5자 이상이고 후보의 60% 이상), 두 문장이면 첫 문장만, 마침표 없는 한글 끝은 수용, 문맥에 없는 문자 체계(결합 부호 포함)는 `FOREIGN_SCRIPT`로 거부. A35 GPU는 "chậm", "များ", "ে" 같은 외국 문자를 자주 섞는다.

## 수집기 결함 수정 (`FcitxInputMethodService`)

앱이 전송 뒤 입력창을 비우면(`setText("")`) 같은 칸이 빈 상태로 재시작(onStartInput restarting=true, 커서 0,0)되거나 커서가 0으로 옮겨진다. 이전에는 "같은 칸 재시작"이라며 대기 문장을 남기거나 마지막 어절만 지워, 다음 메시지 앞에 이전 꼬리가 붙은 문장("…공유드릴게점심 맛")이 최근 보낸 문장·개인 금고에 기록됐다. 두 경로 모두 입력창이 비었으면 대기 문장을 보낸 것으로 확정 기록(flush)한다.

## 남은 것

- 어절 중간에서 쉼표로 시작하는 후보("우산 챙겼" → ", 혹시라도…")가 가끔 나온다.
- 차가운 엔진은 키보드가 숨겨져야 웜업한다(GPU 초기화 중 키보드 멈춤 방지 결정). 그래서 10분 넘게 쉬고 다시 입력하면 그 입력 세션에는 추천이 없다. CPU 백엔드에서는 이 이유가 없으므로 정책을 백엔드별로 나눌지는 사용자 결정이 필요하다.
- 에뮬레이터 IME 경로의 생성 시간(1.1~2.6초)은 엔진 벤치(0.8초)보다 길다. 키보드 UI·다른 예측기와 CPU를 나눠 쓰기 때문으로 보며, 실기기 IME 경로 지연은 아직 재지 않았다(A35는 사용자 실사용 폰이라 개인 금고에 테스트 문장을 학습시키지 않으려고 엔진 벤치만 돌렸다).

## 추가 결정 (같은 날 오후)

- **발열 기준 상향**(사용자 지시 "훨씬 뜨거워도 되게"): 배경 생성 대기·생성 중단은 `THERMAL_STATUS_CRITICAL` 이상만, 문맥 수 1개 제한은 SEVERE부터. 삼성 기기는 충전+부하에서 손으로 뜨겁지 않아도 SEVERE를 보고한다. 에뮬레이터 `cmd thermalservice override-status 3`에서 생성, 4에서 `RESOURCE_THERMAL` 확인.
- **CPU 백엔드는 키보드가 떠 있어도 웜업**(사용자 승인): GPU만 "키보드 숨김 뒤 초기화"를 유지한다. 에뮬레이터에서 키보드 표시 상태로 웜업 5.6초 뒤 후보 표시 확인(`-e hideForWarmup false`).
- **출력 초과로 잘려도 엔진 유지**: `OUTPUT_TOO_LONG`은 대화(conversation)만 망가뜨린다. 네이티브 취소·닫기가 정상이면 따뜻한 엔진을 유지한다(이전에는 놓아서 GPU 기기는 키보드를 숨길 때까지 추천이 끊겼다). 에뮬레이터 CPU·폴드6 GPU 모두 다음 요청이 재초기화 없이 0.5~0.7초에 생성.
- **이모지 거부**: 문맥에 없는 기호 문자(이모지)가 섞인 후보는 `FOREIGN_SCRIPT`로 거부("발🚚 중"), 사용자가 이모지를 쓴 문맥에서는 허용하고 문장 끝 이모지는 문장 끝 판정에서 건너뛴다.
- **폴드6(SM-F956N, GPU) 엔진 벤치**: 19/20 수용, 따뜻한 엔진 중앙값 821ms·최대 1,550ms, 첫 글자 약 0.2초.
